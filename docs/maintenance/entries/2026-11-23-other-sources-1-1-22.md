## 问题与根因
目录的定时检查在 2026-11-23 凌晨（美西）拾取 `fcf4e3b`，结果是 Failed：「Refused by directory policy」。阻断项是「Text tells Claude not to use other tools」（标签 `DP_TAG_BAN`），说明原意：产品里的文字让助手不要用别的工具或来源，这对用户不利，要去掉这种限制；可以说自己的工具擅长什么、为什么。页面不点名文件，也不点名句子。

对比栏写「1 new finding, 1 fixed」：上一版的「Policy review didn't complete」没有了。也就是这一次内容审核读完了，读出了这一条。

同样的文字在 `2f238f8`（2026-11-15 审的）得到的是「Meets directory policy, with warnings」。所以这条检查是 11-15 之后才有或才生效的，不是新写的句子引出来的。

对应的政策条文是 Anthropic Software Directory Policy 第 2 节 E 条：说明性软件不得干扰 Claude 调用其他软件、工具、数据库或资源，除非用户要求。

对照这条，技能里有六处属于这一类：
1. 「未登录」一节：没登录前不给任何酒店价格，不管出自记忆还是网页搜索（1.1.14 加的）。最直接的一处。
2. 同一节「工具结果里带登录链接」那条，重复了同一条规矩。
3. 「先搜索、后提问」那条：要求用搜索工具回答，而不是用常识或网页搜索（1.1.10 加的）。
4. 技能描述：说常识和网页搜索没有这些价格（比较句）。
5. 「要点」一节：价格、可订情况和礼遇只来自 FlyBest 工具结果（可以读成不许用别的来源）。
6. 第 2 节：默认不把客人引到别处去订。

已证实的只有目录的结论和政策条文。「是这几句触发的」是推断；第 1、3 处最像，其余同类一并改。

## 修改方法与原因
- 第 1 处：改成只说 FlyBest 自己的价格、可订情况和合作礼遇要登录后才有，因为它们只存在于工具的实时结果里。其余问题照常回答；用户别的工具和来源给出的信息可以用，要说明出处，并且不能说成 FlyBest 的价格、实时价格或这里能订的价格。每次提醒登录的那条不变。
- 第 2 处：改成一句事实，FlyBest 的价格等工具返回才有。
- 第 3 处：去掉后半句，换成说明这个插件给回答加了什么（实时可订的价格和附带的合作礼遇）。「当轮就搜」不变。
- 第 4 处：描述只说自己有什么，不再和别的来源比。
- 第 5 处：改成「凡是说成 FlyBest 的价格、可订情况或礼遇，都来自 FlyBest 工具结果」。不编造的要求不变。
- 第 6 处：改成正面说法，可订的选项连同对话内的付款页一起给出；客人想走别的渠道就照办。
- README 里和其他旅行工具的对比表是写给人看的产品介绍，政策允许说明自己擅长什么，没有改。
- 版本号 1.1.22：行为有变化，已安装的副本要能看到更新。
- 两条旧记录（1.1.14 和 1.1.10 草稿）各追加一段更正，指向本记录；原文不动。

没动的保护：价格不编造、示例日期的价格不当成报价、合作礼遇只属于列出它的那一行、不接触卡号。

## 用户体验与兼容性
- 装了插件但还没登录的用户：每次酒店或旅行的回答仍然先提醒登录。变化在于助手不再被禁止给参考信息：用户问大概多少钱时，助手可以用自己的知识或用户别的工具回答，同时说明出处，说明那不是 FlyBest 的实时价格。FlyBest 的价格、可订情况和礼遇仍然只有登录后才有，这一点由服务端决定，技能文字改不了。
- 已登录的用户：仍然当轮先搜。少了「不要用常识或网页搜索代替」这半句，助手先凭常识作答的情况可能多一点；多多少没有测。
- 这是对 2026-11-02 店主要求（没登录不给价格）的一处放宽。原因是目录不接受这种限制，不放宽新版本就上不了架。
- ChatGPT 的插件包是另一份上传件，这次不重新提交，仍是 1.1.20 的文字。
- 服务端给公开连接的说明里有同类的三句，在订票服务仓库的记录 `2026-11-23-public-instructions-other-sources` 里处理。
