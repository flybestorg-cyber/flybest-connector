## Problem and cause

Claude Code-based apps (desktop, Cowork, CLI, IDE) and Codex loaded the plugin's server but never started the e-mail sign-in, so the tools never appeared; the 1.1.14 reminder to connect in settings was rarely followed. The service now lets these apps list the tools before sign-in and answers the first lookup with a one-time sign-in link that signs in that chat.

## Change and reason

- Skill: when a tool result says sign-in is needed and gives a link, relay the link unchanged, say nothing was searched yet, and call the tool again after the user signs in, in the same chat; no prices until a tool returns them. It also names the lasting option: connect FlyBest once in Claude (Customize → Connectors → FlyBest → Connect) with the same e-mail. Section 9 points to it.
- README: Claude Code first use now describes the in-chat link instead of `/mcp` authentication.

## Customer experience and compatibility

Users of those apps get the tools at once and a sign-in link on their first lookup; claude.ai web and ChatGPT are unchanged. Older installed versions get the same server behaviour; the tool result itself carries the link and the instruction.
